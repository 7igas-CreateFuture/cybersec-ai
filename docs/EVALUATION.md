# Phase 1 评估事实

## EXP-001

14 个合成样例 × 两模型，28 次真实调用，原始结果在 `evidence/baseline-01/responses.jsonl`。

| 指标 | company-local | cybersec-base |
| --- | --- | --- |
| 完整响应 | 12/14 | 14/14 |
| 主分类严格格式 | 8/10 | 8/10 |
| 格式合规且标签正确 | 8/10 | 6/10 |
| 生成速率中位数 tok/s | 79.90 | 75.37 |

`summary-v2.json` 是严格复评分；旧 summary 保留，不混为第二次模型运行。语义复核是 Codex AI 对输出的审阅，不是人工领域评审。

## EXP-002

同一 cybersec-base 权重、相同参数，现有 system 与冻结候选配对比较。每组 14 条旧回归 + 6 条新增合成题，共 40 次计分调用，另各 1 次不计分预热。

| 旧回归指标 | 现有 system | 候选 system |
| --- | --- | --- |
| 完整响应 | 14/14 | 13/14 |
| 分类格式合规且标签正确 | 6/10 | 8/10 |
| 有效输出误报 | 2 | 0，另有截断 |
| 有效输出漏报 | 0 | 1 |
| 生成速率中位数 tok/s | 76.71 | 76.56 |

新增六题两组标签均为 6/6，但部分修复仍错误。候选存在截断、SSRF题前提歧义，以及混淆订单 ID / 用户 ID 等错误修复。**候选不部署。** 总耗时降低包含输出变短的影响，不解释为推理引擎提速。

原始输出完整保留。元数据中的个人本机路径已脱敏，导出前后哈希见 `evidence/export-manifest.json`；其中 runner_sha256 指历史实验脚本，当前评估器后来增加了检查，不能假定两者字节一致。

## 不能由这些结果推出什么

- 小样本与单 seed 不能证明稳定性能、泛化能力或统计显著提升。
- 格式、标签、证据和修复正确性是不同维度。
- tests 中人工编写的错误/正确反例不是执行模型输出，也不是完整修复评分器。
- cases-v2 尚未推理评测；其标签与旧分数不能混用。
- 原部署验收不能替代此仓库在全新机器上的安装验证。
